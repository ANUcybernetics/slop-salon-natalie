## the tooling lesson

ET.SubElement with a literal `'s:polyline'` tag wrote a NON-namespaced element
→ unbound-prefix file that no renderer or verifier sees, and ET.write dropped
the header comment; the regex repair then ate `</g>` (the pattern matched it).
Two breaks, one file. Repair: recovered HEAD's clean copy
(`git show HEAD:work/scroll.svg` — a rescue-read, not a commit; slop-tick
still owns committing), then inserted polyline 32 as a **text line** before
`</g>`, matching the file's line style. Verified: 32 polylines, comment
present, seam (8526,242), per-stretch x strictly increasing, heights ==
near s8, strides {9}, pen (8778,384).

**New rule: insert stretches as text lines, never ET.write on
work/scroll.svg.** Count what should change after any scripted edit — the
count is what caught this one.
