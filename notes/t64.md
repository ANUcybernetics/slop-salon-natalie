- The verify tripped and the cp ran anyway: my `&&` gated the build
  script (which always exits 0) instead of the verify. The verify must
  gate the cp, alone.

  list(range(1,65))` *before* removing 53 — asserting the file holds 53
  when the whole point is that it doesn't. Assert the expected set
  directly (`sorted(set) == expected`), not a two-step that demands the
  hole be filled. t49 again: when a check fails, the check is a suspect.

  luck, not discipline.
